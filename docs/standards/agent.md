# Agent 工程标准

## 职责

- LLM 负责理解、工具选择和自然语言生成。
- 服务端规则引擎负责确定性计算。
- 工具负责受控数据访问。
- 服务端负责身份、授权和审计。

## Agent 与 Prompt

- Agent ID 稳定唯一。
- Prompt 说明角色、工具、输出格式和失败哨兵。
- Prompt 白名单必须与运行时校验同源。
- 安全边界由运行时执行，不能只写 Prompt。
- 模型升级必须通过 Golden Set 评估。

## 工具

- `createTool` 使用 Zod 输入和输出 Schema。
- 默认只读，结果限量、可序列化、带来源和时间。
- 不接受模型生成的任意 SQL。
- 私有数据查询继承服务端用户权限。
- 写操作必须授权、确认和审计。

## Memory 与线程

- `threadId` 是一段会话，`resourceId` 是真实用户。
- 列表、读取、历史、删除均校验 thread 与 resource。
- 不使用共享 `default-user`。
- 上下文只注入必要消息，敏感信息不进入 Memory。

## API、RAG 与安全

- Chat API 要求登录，校验 Agent、消息、附件和线程。
- 流式请求支持取消、超时、限流和 trace。
- RAG 作为受控工具，结果带来源、时间和实体 ID。
- 向量无结果时降级全文检索，低相关结果不强行入 Prompt。
- 禁止直接执行模型生成的任意代码。
