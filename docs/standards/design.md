# UI 设计与 Preline 标准

## 工作流

1. 先完成需求、数据口径和页面模块澄清，不把猜测直接写进实现。
2. 判断视觉门禁：新增页面、组件、可见状态、交互、信息层级或响应式变化均为“适用”；纯后端/数据且无可见 UI 变化才可标记“不适用”并写明原因。
3. 使用 `oil-ui` 和项目 `ui-design` 确定视觉方向、检查设计冲突并完成原型视觉评审。
4. 从默认参考稿复制到 `docs/design/prototypes/explorations/`，先绘制完整设计稿。
5. 用真实样例、缺失态、错误态、部分成功态和过期态核对桌面、移动端、浅色和深色设计。
6. 用户确认设计稿后，才创建实施计划和 OpenSpec 实现任务；确认前 `tasks.md` 只能包含视觉门禁。
7. 使用 Preline UI + Preline Theme 实现，并用浏览器截图完成视觉 QA。

`oil-ui` 来源为 `oil-oil/oil-ui`，项目内固定在 `.agents/skills/oil-ui/`，所有视觉方向与视觉评审统一使用该 skill。

## 原型

- `initial/` 保存原始稿与当前默认参考稿。
- `explorations/` 保存独立探索稿。
- 不覆盖历史稿；确认后单独更新基准。
- `quant-workbench-assistant.html` 是原始资产，基准快照在 `docs/design/prototypes/initial/`，不得直接改写。
- 当前默认参考稿为 `docs/design/prototypes/initial/quant-workbench-assistant-v2.html`；新设计从该稿复制，原始稿仅用于追溯。

## 主题

- 主题以 `initial/quant-workbench-assistant-v2.html` 为当前默认视觉基准：暖白画布、蓝灰导航、白色内容面板、原始蓝主操作、黄色状态强调、A 股红涨绿跌。
- 核心 token：画布 `#f6f5f1`、导航 `#eef1f7`、面板 `#ffffff`、正文 `#202a42`、次文 `#5f6d84`、主色 `#3157e8`、强调 `#ffd951`。
- 字体沿用原稿的 `SF Pro Display` / `SF Pro Text` / `PingFang SC` 字体栈；数据数字使用等宽数字特性。
- 参考图只用于理解信息密度和页面构成，不作为主题色来源。
- 颜色、字体、间距、圆角、阴影使用语义 CSS 变量。
- `data-theme` 表示视觉主题，`.dark` 表示明暗模式。
- 首屏渲染前恢复主题，避免闪烁。
- 业务组件不得散落 raw hex。

## 页面

- 三区工作台：业务导航、主数据区、AI 助手。
- 桌面工作台侧栏展开宽度 238px、收起宽度 68px；使用原型蓝灰渐变和独立边界色，底部固定“数据状态、系统图标、用户卡片”三层结构。
- 系统入口按角色收敛：`super_admin` 显示“数据管理 + 主题设置”，`user` 只显示“主题设置”；角色未知或加载中按最小权限处理。
- 密集数据用表格和行，不用同尺寸卡片堆叠。
- 主内容左对齐，操作优先级通过对比和留白表达。
- 移动端收敛为抽屉/单列，保持键盘和触控可用。
- 子页面在吸顶页面级导航中使用 `Apollo Quant / 父页面 / 当前页面` 面包屑；父级可点击、当前页不可点击，不显示独立返回按钮。
- 数据管理使用工作台内嵌控制台：页头之后立即展示状态和内容，再提供总览、数据源、数据表、数据同步、数据质量、操作审计二级导航。同步模块使用表格行，不使用卡片堆叠。
- 数据治理嵌入数据管理，固定为“总览、资产与契约、质量证据、来源标准、治理任务、数据事故”。首屏以研究门禁、来源标准漂移和未解决事故为主角；资产与规则元数据只读，运行证据和状态流转可见。
- 治理页面必须覆盖加载、空态、错误、过期证据和最小权限状态；普通用户不渲染任何治理详情，也不在搜索中暴露入口。
- AI 助手抽屉使用“量化助手”标题、真实页面上下文条和“新建、历史、全屏、收起”操作；没有真实未读状态时不显示悬浮按钮通知点。
- 个股分析页使用五行内容状态条表达行情、新闻、公告、研报元数据和研报全文；只有单一“重新分析”主动作，部分失败显示模块级提示，不把整页标成失败。
- 新闻、公告、研报在个股分析页进入同一个按时间倒序的事件列表，来源标签区分新闻、公告和研报；无数据时说明刷新后会进入统一事件流。

## 验收

- 浅色、深色和移动端截图无裁切、溢出或焦点丢失。
- Preline 交互在路由切换后正确初始化并在卸载时清理。
- 图标、图表和状态语义一致。
