# ADR 0004：工作流版本化与独立 Worker

## 状态

已采纳

## 背景

自定义工作流需要在编辑过程中持续保存草稿，同时保证历史运行能准确回放到当时的 DAG。选股、回测、复盘和 AI 因子迭代耗时差异大，不能在 API 请求生命周期内可靠执行。

## 决策

1. `workflow_definition` 保存可变草稿和当前版本号，`workflow_version` 保存不可变图快照。
2. API 只创建 `pending` Workflow Run 并写入 pg-boss；独立 `workflow-worker` 消费并持久化节点状态。
3. 同一工作流通过数据库部分唯一索引限制为一个 `pending|running` 运行。
4. 触发冲突写 `skipped` 记录；节点失败停止下游；取消采用节点边界检查。
5. 运行和节点只保存受限摘要及业务引用，完整业务数据留在选股、回测、复盘或因子模块。

## 取舍

- 放弃直接在定义表覆盖图：无法保证历史运行审计一致性。
- 放弃 API 进程内执行：进程重启会丢失任务且无法限制并发。
- 取消不能强制终止已经发出的外部请求；界面明确提示在途步骤可能完成。

## 验证

- 服务、DAG、数据库约束和前端图校验测试位于对应模块。
- 发布版本、触发冲突、失败阻断、并行 join、取消和恢复由 server 测试覆盖。
