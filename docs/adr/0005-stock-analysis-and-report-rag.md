# 个股分析采用确定性计算与研报 RAG 分离

## Status

accepted

## Context

个股分析同时需要实时行情、历史走势、财务估值、研报全文和情景预测。如果让 LLM 直接生成价格预测或目标价，结果不可复现、无法审计，也会混淆事实、推断和情景。研报 PDF 还存在限流下载、文本提取、扫描件 OCR、页码引用和上下文长度问题。

## Decision

个股分析页面展示的所有数值都由确定性代码计算：

- 行情、技术指标、波动率和历史情景分布由 quant 计算。
- 估值区间由一致预期 EPS 与历史 PE 分位计算。
- 风险参考区间分别展示技术、估值和情景区间，不使用“安全价格”承诺。

研报全文独立进入 RAG 链路：

- PDF 二进制保存在共享 `reports-data` 持久卷，PostgreSQL 只保存路径、SHA-256 和全文字段。
- 原生文本提取优先，文本密度异常时使用中英文 OCR 兜底。
- 研报按章节和页切块，使用本地 `BAAI/bge-small-zh-v1.5` 生成 512 维向量，存入独立 `research_report_chunk`。
- 检索必须按标的和研报发布日期过滤，回答必须包含研报标题、机构、发布日期、页码和原文片段。
- 现有按新闻设计的 embedding 表不复用于研报，也不沿用当前无有效中文 tsvector 配置的查询路径。
- 新闻 RAG 在完成独立设计前不启用；研报 RAG 的长期契约见 [RAG 标准](../standards/rag.md)。

数据获取按 `a-stock-data` 规范实现：行情优先 mootdx/腾讯；研报、资金流和独有数据走东财统一限流；一致预期走同花顺；财务快照/三表走 mootdx/新浪；估值历史走 Baostock；公告走巨潮。生产环境只依赖仓库代码，不依赖 skill 文件。

研报和财务数据先按用户主动分析的标的及自选股同步，不做全市场无差别高频抓取。

## Consequences

- 需要新增研报、PDF 文档、分块、一致预期、财务、估值和分析快照表。
- 需要为 quant 镜像增加 PDF 提取、OCR 和本地 embedding 依赖。
- 需要新增共享持久卷与受控 PDF 下载接口。
- 需要为情景模型建立滚动样本外验证，模型或数据不完整时必须降低置信度。
- 研报原文引用和 PDF 访问必须遵守来源许可及登录权限。
