# Design

## Context

当前根路由持有全局顶栏、主题、通知和账户入口，`/home` 另有业务侧栏与数据页，`/ai-chat` 则使用独立会话布局。现有首页已具备同步状态、行业板块、复盘和研究动作等真实数据，可直接重排，无需新增 API。相关行为契约见 `specs/preline-workbench-ui/spec.md`。

## Goals / Non-Goals

**Goals:**

- 移除应用级全局顶栏，同时保留原型中的吸顶页面级导航条和页面自身标题区。
- 将 `/home/*` 的品牌、业务导航、数据状态、主题和账户入口统一放到侧栏。
- 首页使用现有真实数据形成接近原型稿的信息层级。
- 用一个悬浮助手入口承载快速会话、历史会话和完整会话跳转。

**Non-Goals:**

- 不新增后端接口、Agent 页面数据上下文、数据库字段或行情数据源。
- 不重做复盘、因子、策略、回测、同步等业务页面主体。
- 不删除行情和信号路由，也不将新闻或完整助手页纳入工作台侧栏。

## Decisions

### 根布局只保留主题、认证、页面导航和助手会话状态

根布局移除品牌、全局导航、通知和账户按钮，保留登录后业务页面的 `Page Navigation`、`Outlet`、`Assistant FAB` 和 `Assistant Drawer`。抽屉开关与当前会话 ID 放在根布局，因此业务路由切换时状态仍在；路由变化由路径前值比较触发关闭，重新打开时恢复同一会话。

`Page Navigation` 使用稳定的通用页面名映射，避免动态详情页等待实体查询。面包屑固定以 `Apollo Quant` 为根级，按页面父子关系生成可点击父级和不可点击当前页；独立返回按钮从所有路由移除。它在 `Cmd/Ctrl + K` 时打开仅包含现有页面和操作的搜索面板。

### 侧栏保持现有层级并支持收起

工作台侧栏继续显示现有复盘、量化、系统分组及子项，仅移除行情和信号菜单组。桌面端支持收起为图标栏，导航项保留图标、tooltip 和键盘聚焦名称，收起状态写入本地存储；移动端保持覆盖式侧栏。

替代方案是每个页面各自管理抽屉。该方案会重复状态和 API 逻辑，且跨路由后无法恢复会话，因此不采用。

### 抽屉复用现有 ChatPanel，不复制消息协议

抽屉复用现有 `ChatPanel`、流式 `useChat` 和线程 API，只在外层实现工具栏、历史会话切换、新建会话和完整会话跳转。首次发送沿用现有流程：先创建线程，再将线程 ID 和首条问题交给 `ChatPanel`。已有会话点击展开时进入 `/ai-chat/c/:threadId`，空会话进入 `/ai-chat`。

替代方案是另写一套聊天实现。该方案会复制 SSE、工具调用展示和历史消息转换逻辑，直接淘汰。

### 助手抽屉宽屏避让、窄屏覆盖

宽屏抽屉保持 392px，主内容同步让出右侧空间；1120px 及以下改为覆盖主内容，移动端使用全宽覆盖层。打开时锁定背景滚动、把焦点移入抽屉并支持 Escape 关闭；关闭后焦点回到悬浮按钮。当前页面名称和同步时间只作为界面信息展示，不拼接到聊天请求。

替代方案是所有尺寸都推挤主内容或始终覆盖。前者会让窄屏不可用，后者不符合原型稿的宽屏三区构图。

### 首页去卡片化标题并删除重复 AI 入口

首页标题区改为无边框 `Page Header`，保留真实指标、同步进度、行业板块、最近复盘和研究动作。顶部“问 AI”按钮与独立 AI 卡片删除，悬浮按钮成为唯一全局助手入口；页面内的“AI 迭代”仍作为因子业务功能保留。

### 导航删入口但保留路由

工作台侧栏移除“行情”和“信号”分组，保留现有其它分组。首页的行业板块“全部”等页面内链接继续指向对应路由，因此已有书签、深链接和页面间业务跳转保持可用。

### 侧栏严格采用确认原型的信息架构

一级信息架构固定为“工作空间、市场情报、量化研究、流程自动化”。工作空间承载每日看板、工作任务、每日复盘和每日选股；市场情报承载行情中心和研报洞察；量化研究承载策略、因子、回测、衰退对比和因子迭代；流程自动化承载工作流。分组标题始终可见，子项全部展开。原有但不在确认原型中的菜单入口不再展示，路由仍可直达。

系统能力从主业务导航视觉层中弱化，放在数据状态胶囊和用户卡片之间，仅提供同步中心、数据中心和主题设置三个 33×33px 图标按钮。展开时按 6px 间距横向紧凑排列，侧栏收起时转为 5px 间距的纵向排列并保留 tooltip；账户入口继续使用独立用户卡片。侧栏沿用原型的渐变表面，不绘制右侧边框。

### 工作台先回答数据可信度和今日动作

工作台顺序调整为页面标题、今日状态条、行业板块与数据健康双栏、今日工作流、研究快捷入口、最近复盘。今日工作流本轮显示开发中空状态；未来列表按 Workflow Run 展示名称、触发时间、当前步骤、状态和耗时。

### 每日看板通过单一聚合接口读取真实快照

生产每日看板使用 `/api/v1/dashboard` 聚合读取板块历史、资金流排行、涨停池、股票池、新闻和最近复盘。市场日期、资讯日期、复盘日期和工作流日期分别展示，不以当前日历日期替代行情日期。

页面首屏展示数据状态与四项核心指标；后面依次展示行业/概念资金主线、市场温度与连板梯队、每日选股、用户工作流、资讯增量和最近复盘。模块通过现有路由下钻，不复制生成或运行操作。缺少数据时保留模块并展示真实空状态。

### 复盘采用归因入口与页面内往返

工作空间只保留“每日复盘”一个入口，默认进入最近交易日复盘页。今日页标题使用“每日复盘”并通过副标题说明最近交易日，标题操作区提供“历史复盘”按钮；历史页保留“历史复盘”标题，并通过面包屑父级返回每日复盘。两个独立路由与数据行为不变。

## Risks / Trade-offs

- **行情和信号入口变弱** → 通过首页行业板块和既有页面内链接保留可发现路径，并在 ADR 中记录这是有意选择。
- **抽屉流式会话状态与完整助手页并存** → 复用同一线程 API 和 `ChatPanel`，首次发送后立即保存线程 ID；完整页跳转只切换承载容器。
- **移动端覆盖导航** → 抽屉使用全宽布局并提供显式关闭和 Escape；关闭后焦点返回悬浮按钮。
- **真实数据不足导致首页不如原型饱满** → 保持现有真实区块的层级与留白，不使用假行情或占位指标。
- **行情快照明显滞后** → 在首屏持续展示数据日期和滞后天数；各模块继续展示最新完整快照，不包装为实时数据。

## Migration Plan

本次只改前端。先落地无顶栏与应用根布局，再完成首页重排和助手抽屉；新闻与完整助手页补充返回工作台入口。回滚时恢复根布局的全局顶栏、首页重复 AI 入口和侧栏菜单分组，数据与数据库无需迁移。
