# Design

## Context

个人工作任务功能已经完成，但生产视觉沿用了旧原型中的黑色视图 Tab 和额外表面层级。V2 设计稿已统一主色、语义表面、默认主题和助手侧栏，并完成用户确认。

## Goals / Non-Goals

**Goals:**

- 生产页面与已确认 V2 视觉基准一致。
- 浅色和深色主题使用同一套语义变量。
- 保持任务交互、数据口径和接口行为不变。

**Non-Goals:**

- 不修改任务 API、数据库和来源快照。
- 不新增任务编辑、状态或拖拽能力。
- 不调整其他业务页面的信息架构。

## Decisions

### Default to light theme

首次进入默认浅色，与视觉基准一致。`system` 仍作为用户可选项，但只有显式选择后才读取系统偏好。

替代方案是继续默认跟随系统，但同一用户首次打开会看到两套视觉主题，无法稳定验收原型。

### Use one semantic surface hierarchy

工作任务页使用“页面画布 → 任务卡”两层表面。看板列保持透明，仅在拖拽命中时显示主色反馈；不再额外包裹灰色看板底板。

### Use accent-strong for selected Tab

浅色主题使用品牌蓝，深色主题使用更深的品牌蓝，保证白字对比度。Tab 与侧栏选中态使用同一语义。

### Keep assistant inside the active theme

助手侧栏、上下文条、消息气泡和输入框使用当前主题的 `panel/surface/line/ink` token。不得固定为浅色或深色独立主题。

## Risks / Trade-offs

- **默认浅色改变系统深色用户的首次体验** → 保留“跟随系统”设置，用户可显式恢复。
- **全局默认主题影响其他页面** → 设计标准同步写入 `docs/standards/design.md`，所有页面共享同一规则。
- **视觉调整影响点击区域** → 保留原有按钮语义和尺寸要求，并通过桌面/移动端截图复验。

## Migration Plan

1. 更新默认主题初始化和测试。
2. 对齐工作任务页、看板、侧栏和助手侧栏。
3. 运行 Web 测试、类型检查、lint、构建和浏览器截图。
4. 用户验收后再归档。
