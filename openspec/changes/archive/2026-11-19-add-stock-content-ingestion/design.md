# Design

## Context

见 `proposal.md - Why`。当前个股新闻由 TypeScript 新闻管道直接请求东财，绕过 quant Provider 的统一东财限流；新闻入库后只依赖正文代码识别个股，未把本次查询标的强制关联。公告没有生产链路，研报只有个股分析手动元数据同步。数据管理运营注册表也没有收录这些内容表。

## Goals / Non-Goals

**Goals:**

- 用现有 Provider → registry → router 架构接入个股新闻和公告，并统一东财限流边界。
- 让新闻、公告和研报同时支持自选股定时同步与任意个股按需刷新。
- 用稳定业务键和显式个股关联保证可重复执行。
- 把 10 张内容表及其来源、任务和血缘放入数据管理。
- 为内容资产产生 Tier 1 质量证据。

**Non-Goals:**

- 不采集全市场每只股票的新闻、公告和研报。
- 不提供实时流推送、全文情感模型或新的 AI 摘要功能。
- 不自动提取所有研报 PDF；PDF 全文仍由用户对单篇研报触发。
- 不改变行情 Provider 优先级、PIT 复权或 `load_kline` 契约。

## Decisions

### Visual design

沿用已确认的个股分析工作台，不新增页面或助手入口。顶部保留单一“重新分析”主动作，其下用五格状态条分别表达行情、新闻、公告、研报元数据和研报全文；公告降级或失败使用黄色/红色状态，不把整页标成失败。新闻与事件卡改为按时间倒序的统一事件流，来源标签区分新闻、公告和研报。

探索稿：`docs/design/prototypes/explorations/quant-workbench-stock-content-v1.html`。

桌面/移动端、浅色/深色和部分失败截图：`docs/design/prototypes/explorations/screenshots/stock-content-v1/`。

### Provider capabilities

新增两个能力：

- `stock_news`：东财主源、Sina 备源，返回标题、正文、时间、URL、来源和关联标的。
- `announcement`：巨潮主源、东财备源，返回公告标题、类型、发布时间、来源标识和原文/PDF URL。

研报不新增能力，继续使用现有东财研报 Provider。

备选方案是继续在 `news.ts` 中直连 HTTP，改动更少，但违反统一 `_em_get()` 约铁律，也没有可测试的降级链。拒绝。

### Server ingestion service

新增统一的个股内容服务，负责：

- 调用 quant 内容端点。
- 将新闻、公告、研报按稳定键幂等写入。
- 新闻始终关联当前查询标的，再合并正文识别出的其他有效标的。
- 返回每个内容模块独立的 `ok / inserted / total / error / observedAt`。

个股分析刷新 API 并行执行三个模块；单模块失败不取消其他模块请求。

备选方案是让前端分别调用三个 API，但会重复身份、门禁和错误聚合逻辑。拒绝。

### Synchronization

- 新闻：现有每 2 分钟任务继续运行，自选股个股新闻改为调用 `stock_news` Provider。
- 公告：新增交易日收盘后任务，按自选股执行最近 30 天增量。
- 研报：新增每日任务，按自选股同步最近 12 个月元数据；单股刷新使用相同服务。
- 首次回填使用相同窗口，不抓完整历史。

### Data management metadata

复用 `DATA_CENTER_TABLES` 作为数据表、数据源和数据同步页面的代码注册表。主表展示外部来源和降级链；派生表展示上游资产、生成任务或无外部来源。治理注册表继续作为完整资产契约事实源。

备选方案是只保留在治理目录，但用户无法从日常数据管理页面看到同步与表状态。拒绝。

### Quality

为新闻、公告和研报增加 Tier 1 warning 规则：

- 新鲜度使用 `fetched_at` 或最近可用检查时间，避免低频公告被误判。
- 必填字段和业务唯一键来自治理契约。
- 新闻个股关联覆盖使用 `news_article_symbol` 汇总。
- 研报文档检查 PDF 元数据是否符合已提取状态。

任何内容质量告警都不参与 Tier 0 研究阻断。

## Risks / Trade-offs

- 新浪备源是全局 7×24 流，目标股票可能不在当前页 → 使用更大页面并在无命中时返回空，保持主源优先。
- 自选股数量增长会线性增加上游请求 → 串行执行并复用 Provider 限流，后续再按规模分批。
- 研报元数据和 PDF 全文是不同成本层级 → 默认只同步元数据，全文按单篇触发。
- 公告唯一约束迁移在已有重复数据上失败 → 迁移前只保留最新重复行，其他行删除前先输出数量并在回滚说明中记录。
- 数据源部分失败 → 刷新响应保留模块级状态，页面不得把整次刷新描述为全成功。

## Migration Plan

1. 先上线 Provider 和 server 落库服务，保持现有页面读取行为。
2. 上线公告唯一约束迁移和数据管理元数据。
3. 上线质量规则，保持 warning。
4. 开启自选股新闻、公告和研报定时任务。
5. 上线统一刷新响应和前端状态。

回滚：

- 停用新增公告与研报定时任务，恢复新闻任务到现有入口。
- 保留已写入新闻、公告、研报和质量证据，不删除业务数据。
- 前端可继续读取旧表；质量规则保持 warning，不影响研究门禁。
