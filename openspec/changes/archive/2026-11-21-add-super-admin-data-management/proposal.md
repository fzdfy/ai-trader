# Proposal

## Why

数据源、数据表、同步依赖、熔断、断档和运维操作目前分散在文档、数据中心、同步中心与日志中。普通用户也能访问数据基础设施信息，且同步触发接口没有管理员鉴权。需要把稳定知识保留在文档中，同时提供一个受超级管理员保护的统一数据管理入口。

## Product Requirements

### Users

- `user`：只能看到主题设置，可使用工作台中不敏感的聚合数据状态。
- `super_admin`：可进入“数据管理”，查看数据源、数据表、同步任务、数据质量和操作审计。

### Goals

- 统一说明数据从哪个来源进入哪张表、由哪个同步任务写入、何时更新以及失败后如何处理。
- 复用现有数据中心和同步中心能力，不新建独立后台应用。
- 以代码注册表和环境变量作为数据源配置事实源，后台只读展示并叠加运行时状态。
- 一期支持查看、单模块重试和手动同步；所有操作都受权限、范围、并发和审计约束。

### Success Metrics

- 用户能在 3 次点击内从“数据管理”到达任一数据源、数据表或同步模块。
- 任一数据表可追溯到来源、同步任务、依赖、最近更新时间和最近运行结果。
- 非 `super_admin` 无法通过菜单、直接 URL 或 API 访问数据管理内容。
- 手动同步和重试均可通过审计记录定位操作者、时间、范围、参数和结果。

### Non-Goals

- 不提供任意 SQL、业务数据行直接编辑或在线修改 Provider 凭据。
- 不在首期开放历史回补、派生数据重建、暂停调度和删除任务。
- 不让普通用户查看数据源健康、熔断、任务错误和数据断档详情。
- 不复制现有同步执行引擎，也不新增独立管理服务。

### Acceptance Criteria

- `super_admin` 看到“数据管理”，其中包含同步中心和数据中心；`user` 只看到主题设置。
- 非超级管理员直接访问数据管理页面会回到工作台，直接请求管理 API 返回 `403`；未登录请求返回 `401`。
- 工作台仍可向普通用户显示不敏感的“数据在线 / 最近更新”聚合状态。
- 一期数据中心只展示目录、Schema、来源、同步策略、统计和运行记录，不返回原始数据行。
- 一期动作只包含手动同步和单模块重试，并记录审计日志。

## What Changes

- 新增 `role-based-admin-access`：定义 `user`、`super_admin` 角色和首次超级管理员引导。
- 新增 `data-operations-console`：提供数据源、数据表、数据同步、数据质量和操作审计页面。
- 修改 `preline-workbench-ui`：底部系统入口按角色显示；工作台保留聚合数据状态。
- 为数据中心与同步中心 API 增加服务端授权，不允许仅依赖前端隐藏菜单。
- 新增管理员操作审计，覆盖手动同步和单模块重试。
- 保留现有数据中心注册表与同步引擎，重构为“目录读模型 + 受控动作”。

## Capabilities

### New Capabilities

- `role-based-admin-access`: 角色模型、超级管理员引导、页面与 API 授权边界。
- `data-operations-console`: 数据源、数据表、同步、质量、受控动作和审计。

### Modified Capabilities

- `preline-workbench-ui`: 系统菜单可见性按角色变化，并保留普通用户的数据状态摘要。

## Impact

- Web：侧栏系统入口、数据管理页面、同步中心、数据中心、无权限页面和普通用户数据状态。
- Server：角色校验、数据中心与同步 API 授权、单模块重试、审计记录。
- Database：用户角色字段、管理员操作审计表。
- Quant：复用现有来源健康与同步能力，不新增独立管理服务。
- 文档：更新数据中心、同步中心和权限相关长期标准。
