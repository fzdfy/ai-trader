# Proposal

## Why

研报检索和 Agent 工具已经有向量检索代码，但当前数据库中没有 PDF 文档、分块或向量，实际检索只能返回空结果；新闻也没有生成或使用向量。用户需要把“研报 RAG 代码路径”补成可自动补全、可降级、可验证的完整研究能力，同时明确新闻暂不属于 RAG。

## PRD-lite

### 目标用户

- 进入个股分析页、希望围绕研报主题快速找到可引用证据的研究用户。
- 使用 AI 助手询问个股研报观点、需要按页码追溯来源的 Agent 用户。
- 管理内容同步与质量状态的数据运营人员。

### 核心场景

1. 自选股在交易日收盘后同步研报元数据，用户进入分析页立即看到本地列表。
2. 非自选股首次分析时后台同步一次元数据，不阻塞首屏。
3. 元数据可用后，后台自动补全当前标的最近 30 天研报全文、分块和向量。
4. 用户搜索主题时看到带标题、机构、日期、页码和片段的证据；向量为空或失败时自动改用关键词。
5. AI 助手基于 Top 5 证据生成 RAG Answer，并引用实际使用的研报。

### 成功标准

- 自选股已同步元数据后，进入分析页不需要额外等待上游请求即可展示列表。
- 当前标的最近 30 天研报在后台完成索引，单篇失败不阻塞页面或其他研报。
- 语义检索为空时不会直接返回空集合，关键词降级有测试证据。
- 20 条 Golden Set 中每条至少命中一个预期研报证据；所有 RAG Answer 引用都可回溯到实际证据。
- 不产生新闻向量，不把新闻检索描述成 RAG。

### 非目标

- 不启用新闻 RAG。
- 不为全市场自动提取全部 PDF。
- 不让 LLM 生成目标价、安全价格或确定性收益。
- 不重做现有个股分析页面视觉语言。

## What Changes

- 新增独立 `research-worker`，通过 pg-boss `research-report-index` 队列串行执行 PDF 下载、提取、OCR、分块和向量化。
- 新增全文索引触发 API：页面读取完成后可提交标的级索引请求；GET 分析接口保持只读。
- 自选股依赖现有 `18:10` 元数据任务；非自选股首次进入后台同步一次最近 12 个月元数据，同一标的 24 小时内不重复自动请求。
- 元数据可用后自动补全当前标的最近 30 天全部研报，成功项跳过，失败最多重试 3 次。
- 语义检索返回空集合时降级关键词检索；Evidence Search 返回 Top 8，Agent 注入 Top 5。
- 在现有“研报全文”状态格展示索引中、已完成和部分失败，不新增独立页面或弹层。
- 增加 Golden Set 验证、运行状态、错误证据和文档。
- 新闻 RAG 保持禁用；清理或隔离失效的 `news.embedding` 查询代码，避免被误接入。

## Capabilities

### New Capabilities

- `research-rag`: 研报全文索引入队、后台执行、检索降级、引用契约、状态追踪和 Golden Set 验收。

### Modified Capabilities

- `stock-content-ingestion`: 增加非自选股首次分析的后台元数据同步语义，并明确元数据同步与全文索引是不同阶段。

## Visual Design Impact

Visual design: required

- 受影响界面：个股分析页现有“研报全文”状态格、研报列表与 Evidence Search。
- 新增可见状态：等待索引、索引中、全部完成、部分失败、全文证据不足。
- 不新增页面；继续使用 `quant-workbench-stock-content-v1.html` 的工作台层级。
- 需要生成独立探索稿和桌面/移动端、浅色/深色截图，并在生产代码前由用户确认。

## Impact

- 前端：分析页读取索引状态，自动提交标的级全文索引请求，展示聚合进度并轮询刷新。
- Server：新增研究索引入队接口、状态查询与 trigger dedupe；新增 research-worker 及 pg-boss 队列。
- Quant：复用现有 PDF 提取、OCR、分块和 BGE embedding 能力；补足错误分类和结果契约。
- 数据库：复用研报、文档、分块和预测表；增加队列/状态所需的最小持久化能力。
- 运行环境：新增独立 worker 容器，全局并发 1，避免 OCR 和 CPU 影响 API 或工作流执行。
- 验证：比亚迪与非自选股各一组，至少 20 条查询-证据 Golden Set。
