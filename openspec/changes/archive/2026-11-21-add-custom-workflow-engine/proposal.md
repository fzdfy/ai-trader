# Proposal

## Why

当前“工作流”只有前端占位页，用户无法把选股、回测、复盘和 AI 因子迭代组合成可复用的自动流程，也无法查看今日运行状态。需要一个可编辑、可发布、可调度、可审计的自定义 DAG 工作流系统。

## What Changes

- 提供私有工作流定义、草稿、发布版本、启停与归档管理。
- 提供画布式 DAG 编辑器，支持节点面板、拖拽、连线、删除、缩放、适配画布、配置抽屉、撤销/重做和发布前校验。
- 支持手动、交易日定时、指定同步模块完成后三类触发器；每个工作流必须且只能有一个触发器。
- 支持股票池、运行选股、回测、生成复盘、AI 因子迭代五类动作节点。
- 支持最小类型化数据传递：股票池和选股输出 `symbols[]`，回测逐只执行并汇总，最多 50 只；不开放任意 JSON 变量。
- 使用不可变发布版本执行；运行记录绑定具体版本，支持运行详情、节点状态、耗时、错误和取消。
- 同一工作流只允许一个活动运行；运行中再次触发会跳过并记录原因；节点失败停止下游，不自动重试。
- 工作流运行历史保留 90 天；删除采用归档，历史运行继续可查看至过期清理。
- 工作台“今日工作流”从开发中占位改为展示真实 Workflow Run 的名称、触发时间、当前步骤、状态和耗时。

## Capabilities

### New Capabilities

- `workflow-orchestration`: 工作流定义、版本、触发器、DAG 执行、运行记录、取消、归档和保留策略。
- `workflow-authoring-ui`: 工作流列表、画布编辑、节点配置、发布校验、运行详情和工作台今日运行摘要界面。

### Modified Capabilities

无。

## Impact

- 前端：工作流列表/画布/运行详情、首页运行摘要、数据请求 hooks。
- 后端：工作流 API、图校验、版本发布、执行协调器、运行查询。
- 数据库：工作流定义、不可变版本、运行、节点运行、调度记录。
- Worker：基于现有 `pg-boss` 的工作流队列消费者和调度器。
- 依赖：前端新增 `@xyflow/react` 图编辑依赖。
- 现有能力：复用选股、回测、复盘和 AI 因子迭代逻辑；需要将路由内业务逻辑提取为可调用的服务，不通过服务端 HTTP 自调用。
- 安全：工作流默认仅创建者可访问；API 使用 Better Auth 会话身份，不信任 `X-User-Id`。
